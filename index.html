01

About

What I do, and what I'm actually good at.

I've spent the last year testing one fintech application across Android, iOS, the web, and USSD over the mobile network. Same product, four ways of reaching it, and four different sets of failure modes.

Most of my work is functional, regression, smoke, sanity and exploratory testing, plus integration and acceptance testing as features move from first build to release. I validate REST APIs in Postman (payloads, status codes and edge cases) before anyone opens the UI.

I've automated 50+ smoke and SIT cases so a new build proves itself before a person looks at it. Defects go into Jira with reproduction steps, screenshots and logs, and I retest fixes with the developers until they hold.

I also use AI tools to help write test cases, draft test plans and debug automation scripts, which has cut a surprising amount of test preparation time.

Plant Health Detection System

Python · CNN · Flask

A deep learning plant disease classifier behind a Flask web interface. My part was the interface, not the model.

What I tested

  • Functional behaviour of the Flask web interface
  • UI input scenarios for the image upload path
  • How the interface behaves when a prediction is wrong or absent

Interesting problem

A wrong classification is a model problem, not a loggable defect. What is mine to test is the Flask layer around it: whether the interface stays honest when the prediction underneath is wrong, slow, or missing.

Weather Forecasting Web App

HTML · CSS · JavaScript · OpenWeather API

Two halves of one feature: an external API that can return anything, and a front end that has to behave sensibly whatever comes back.

What I tested

  • OpenWeather API responses checked for accuracy
  • Cross browser functional testing of the interface

Interesting problem

Any external API fails in ways the specification never mentions. The useful question was never does the request work, but what does the page do when it doesn't.
