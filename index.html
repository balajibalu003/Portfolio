01

About

What I do, and what I'm actually good at.

I've spent the last year testing fintech applications across Android, iOS, the web, and USSD over the mobile network.

Different apps, four ways of reaching a user, and four different sets of failure modes. Most of my work is functional, regression, smoke, sanity and exploratory testing, plus integration and acceptance testing as features move from first build to release.

I validate REST APIs in Postman (payloads, status codes and edge cases) before anyone opens the UI. I've automated 50+ smoke and SIT cases so a new build proves itself before a person looks at it. Defects go into Jira with reproduction steps, screenshots and logs, and I retest fixes with the developers until they hold.

I also use AI tools to help write test cases, draft test plans and debug automation scripts, which has cut a surprising amount of test preparation time.

Plant Health Detection System

Python · CNN · Flask

A deep learning plant disease classifier behind a Flask web interface. My part was the interface, not the model.

What I tested

  • Functional behaviour of the Flask web interface
  • UI input scenarios for the image upload path
  • How the interface behaves when a prediction is wrong or absent

Interesting problem

A wrong classification is a model problem, not a loggable defect. What is mine to test is the Flask layer around it: whether the interface stays honest when the prediction underneath is wrong, slow, or missing.
